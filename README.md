# 投标评分分析工具

纯静态应用，桌面入口为 `index.html`，移动入口为 `mobile.html`。所有项目数据保存在当前浏览器，不上传到服务器；跨设备使用项目 JSON 文件导入/导出。

## 使用流程

1. 在「项目工作区」新建或复制项目，设置评分规则。三项分值构成合计100；商务、技术设置录入满分，价格设置招标公式使用的满分，分别配置。
2. 在样本区域录入数据，或从 Excel 复制制表符分隔的「名称、报价、商务分、技术分」，预览后追加。可停用样本；「均价基准＋节点分段插值」及「合格均价×系数双向扣分法」须补齐全部参与样本的有效评标价，其余规则空报价不参与排名。
3. 查看价格/综合评分。得分相同采用并列名次（1、1、3）；修改输入后，旧结果会提示重新计算。可按报价、价格排名或综合排名排序。
4. 搜索时填写报价范围、步长与底线。可选第一情景占比、最差分、加权平均分，或全部情景达到目标分后选较高报价。表格情景支持任意样本数量和正权重。
5. 保存方案会保存当时的规则、全部样本和搜索输入。可恢复为新项目重新计算；旧版方案仅有摘要，不能补造历史输入。
6. 导出项目文件用于备份/转移；导出 HTML 报告可打印为 PDF，含计算规则、样本与结果及完整复核数据。

## 价格公式分与综合分

价格原始分由招标公式计算；价格分值决定它占综合分多少分。**价格计入综合分 = 价格原始分 × 价格分值 ÷ 价格公式满分**，各项贡献不提前舍入，综合分合计保留四位。页面和报告分别显示原始分与贡献。

例如商务/价格/技术分值为10/35/55，招标价格公式从100分扣分，则价格分值填35、价格公式满分填100。七个复核价格为116万、98万、121.5万、125万、125万、139.5万、146万元时，均值×0.9的基准价为1,119,857.142857…元；125万元的价格原始分94.19，价格计入综合分32.9665/35。商务、技术可分别按实际10/55分录入。

也允许价格公式本来就是35分制。公式满分35且扣分0.5/0.25时，上例价格分为29.19，不能与100分公式混用。系统提供口径提示，不强制改成100或自动缩放扣分系数。加载、导入、恢复历史项目均保留已存参数；主动切换策略会采用该策略的推荐公式满分，之后仍可调整。

## 均价基准＋节点分段插值

在价格策略中选择「均价基准＋节点分段插值」。基准价 A 为所有参与样本**经复核后的最终评标价**的算术均值，不去高低、不乘系数；K =（评标价 − A）÷ A × 100%。系统不执行报价复核或资格审查，调整后的价格由使用者录入，不合格样本应停用。

- 节点、左右端固定分和价格分舍入口径均可编辑；每行填写「偏差百分数 得分」，例如 `-5 100`。
- 参考曲线：`-11→80、-10→90、-9→93、-8→95、-7→97、-6→99、-5→100、-3→100、-2→95、-1→90、0→85、1→80、2→75、3→60`。相邻节点之间线性插值，−5%～−3%为100分平台，K≤−11%固定80分，K≥3%固定60分。
- 若商务、技术按百分制录入，价格使用100分公式，商务/价格/技术占比为10%/20%/70%，分值构成依次填 `10、20、70`，商务/技术录入满分及价格公式满分均填 `100`。选择价格策略不会改写分值构成。
- A和K不提前舍入，默认价格分保留计算精度、显示两位小数；也可明确选择先舍入至0～6位。仅消除节点边界的机器精度误差。综合分沿用四位小数；界面同为两位小数不表示未舍入得分必然相同。
- 未填或无效的参与报价会阻止计算，也不能静默从当前样本生成缺项情景。填写完整或停用后再算；自行输入的独立情景按其列出的样本计算。

桌面、移动端、后台搜索、规则模板、项目导入导出及方案快照共用该配置。确认配置后可以保存为自己的规则模板。

## 计算与数据边界

- 如采用“合格投标人复核后的评标价格算术平均值×90%，基准价100分，高于每1%扣0.5分、低于每1%扣0.25分，最低0分”的规则，选择「合格均价×系数双向扣分法」，默认系数为0.9、高价扣分为0.5、低价扣分为0.25，价格公式满分为100。可按实际文件调整参数。
- 上述规则须将人工复核后的最终评标价格填入报价栏；在「批量录入与参与状态」停用不合格样本。程序不自动判定资格，也不自动修正算术错误、漏项或超范围报价。全部已启用样本均须填写有效评标价，缺失时提示补齐或停用，不静默漏算；其余全部计入平均值，不去高去低。
- 基准价和偏差率用于计算时不提前舍入，页面显示的基准价最多6位、偏差率两位；价格分按现有系统口径保留两位小数。招标文件另有舍入规定时，应按其规定核对。例：四个合格评标价为81、90、99、130元，平均值100元、基准价90元，对应价格分为97.50、100.00、95.00、77.78分。
- 满分、基础分、上下限、系数及分档配置必须相容。不足以执行去除规则时明确报错，不自动更换计算方法。
- 价格公式满分以项目的`priceFull`为准；加载时不再由旧`outlierFullScore`等影子参数覆盖，分档最高分可以小于公式满分。平均价法未指定最高分时仍以公式满分为上限。
- 报价输入保留原文与数值，刷新、跨端和点击计算不会截去原始报价小数；非法输入会保留供修正。报价评分页与综合评分页共用报价数据。修改后旧结果失效，排序继续展示当时的规则和旧结果提示。
- 情景文本的逗号可能与千位分隔符冲突：建议使用无千位分隔符的金额，以分号分隔；有歧义时拒绝猜测。Excel 单元格内的规范千位分隔符可以识别。
- 搜索结果是当前范围、步长和所列情景下的候选优选。达到目标分的区间仅涵盖已搜索点，不能推断步长之间或未输入情景的表现。
- 情景占比按相对权重计算，不是实际胜出概率。默认仅按价格公式；启用技术分特殊条件时，必须提供目标与全部其他样本的有效技术分。
- 正式评分与搜索共用参与过滤、数值检查和价格排名，停用样本不纳入计算。未舍入插值分的真实差异仍参与排名，不另外放宽搜索的同分判断。情景权重稳定归一化后汇总；超出有效计算范围时明确报错。
- 两端共用同源浏览器存储；不同浏览器/设备不会自动同步。旧桌面存储保留作为迁移来源。并发页面有更新时拒绝旧页面覆盖，支持先导出未保存输入。
- 配额不足或存储不可用会明确显示“未保存”，不宣称保存成功。清理浏览器数据会删除本机项目，应定期导出备份。
- 无法读取的工作区不会覆盖原存储，可用“导出原始存储备份”保留恢复资料。导入、读取和模板写入检查结构；节点文本、未填的搜索值等可编辑草稿仍可保存，语义错误在计算前提示。

## 开发与验收

共享模块：`js/rules.js`管理策略目录、参数、默认配置与预设；`js/rule-ui.js`渲染两端共同的规则编辑与折算说明；`js/scoring.js`负责计算和排名；`js/workspace.js`负责持久化；`js/workspace-ui.js`负责项目与报告等公共交互，两端入口保留各自布局。新增策略时同步规则目录与计算实现，避免再分别复制两端参数表。

本轮设计检查、优先级与复现见[系统设计检查记录](docs/system-design-review-2026-11-01.md)。

建议 Node.js 22。运行 `npm ci` 后执行：

```sh
npm test
npx playwright install chromium
npm run test:browser
```

页面测试自行启动仅监听127.0.0.1的临时服务，使用隔离浏览器上下文，结束后关闭服务与浏览器。可使用 `CHROMIUM_PATH` 指定已有 Chromium，使用 `PLAYWRIGHT_MODULE` 指定测试运行时，`SMOKE_ARTIFACT_DIR` 保存验收截图。

`layout-browser.cjs`由页面测试入口统一执行，覆盖桌面四页、手机五页、10种策略编辑器及导出报告。使用长名称、完整评分、多情景和并列第一数据，检查页面/卡片外溢、同级控件重叠、单元格内容及窄屏表格滚动。

公共工作区、参数编辑器和结果工具的布局维护在`css/workspace.css`；桌面布局在`css/style.css`，手机卡片在`mobile.html`。表单按语义分组，栅格子项保留`min-width:0`，宽表格放入有提示和键盘焦点的独立滚动区域；新增字段需同时复验长标签、长名称及窄屏，避免依靠固定输入宽度压缩整页。

本地预览可运行 `python3 -m http.server 8765 --bind 127.0.0.1`。后台搜索使用 Web Worker，应通过 HTTP 服务打开，不直接使用 `file://`。

发布工作流在评分测试和页面流程测试通过后，仅将页面、JS、CSS打包到 Pages。修改部署工作流本身不表示已经部署。
